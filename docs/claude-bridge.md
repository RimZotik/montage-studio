# Связь с Claude

Как приложение разговаривает с Claude Code: чат с разобранным потоком событий, терминал,
сборка подсказки из правил и выделения, инструменты студии через MCP.

## Назначение

Claude работает с проектом как второй монтажер: видит правила проекта, выделение на таймлайне и
файлы, правит проект только инструментами студии (с отменой), а ответы и действия показываются
в привычных панелях, а не простыней текста.

## Как устроено

### Два способа

- **Чат** (панель «Claude», основной): ядро запускает `claude` в папке проекта в режиме без окна —
  `-p --input-format stream-json --output-format stream-json --verbose --include-partial-messages`,
  плюс `--append-system-prompt-file`, `--mcp-config`, `--permission-mode`, `--resume <сессия>`.
  Процесс живет, пока открыт проект; сообщения пользователя уходят в его вход строками JSON,
  события читаются из выхода. Сессия сохраняется в проекте — разговор продолжается после
  перезапуска.
- **Терминал** (панель «Терминал», второстепенный): обычный интерактивный `claude` (или
  оболочка) в pty в папке проекта — для всего, что удобнее руками. MCP студии подключен и там (`.mcp.json` проекта).

Флаги сверять с `claude --help` установленной версии; поддерживаемая версия — в манифесте
компонентов.

### Как сделано сейчас (0.4–0.5, `src-tauri/src/chat/`)

- Модель — `--model` из настроек (по умолчанию Sonnet: быстрее и экономнее на простых
  командах; Opus — для сложного), выбор — в шапке чата; смена модели перезапускает процесс с той
  же сессией. Справочник Claude о студии — описания инструментов MCP и постоянный контекст: они
  в начале каждого хода и кэшируются (повторно стоят ~10 % цены), поэтому «разрежь» или
  «сделай тише» Claude выполняет сразу, не изучая студию заново.
- Внешний Claude (разработка): сборка разработки (или `MONTAGE_MCP_EXPOSE=1`) пишет адрес и ключ
  MCP в `%APPDATA%\<app-id>\mcp-dev.json` — те же инструменты доступны снаружи для проверки.
- Процесс запускается при первом сообщении и живет, пока открыт проект; меняются правила
  проекта — перезапуск с той же сессией (`--resume`), сессия — `.studio/claude/session.json`.
- **Изоляция от личного окружения** пользователя — меньше токенов на ход (замер: запуск ~10,6
  тыс. токенов вместо ~33 тыс.): `--setting-sources project`, `--strict-mcp-config` с пустым
  `mcp.json`, `--disable-slash-commands`, `--no-chrome`, `--tools Read,Glob,Grep,Edit,Write`.
  Вход по подписке при этом работает (`--bare` не годится — только API-ключ).
- **Разрешения:** без вопроса — чтение и правка `rules/**`; остальное отклоняется, отказ виден в
  итоге хода карточкой «Не разрешено в студии» (`permission_denials`). Диалог разрешений — с
  MCP-сервером студии.
- Пока нет MCP студии, карточки предложений и вопросов — блоки ```` ```studio-proposal ```` и
  ```` ```studio-ask ```` в тексте ответа (`src/panels/Claude/blocks.ts`), решение возвращается
  служебной строкой.
- Живая проверка — `cargo test live_chat_turn -- --ignored --nocapture` (правка правил
  разрешена, запись вне `rules/` — запрещена и видна в итоге хода).

Чат — основной способ: окно общения как в приложениях-помощниках (сообщения, Markdown, код с
подсветкой, вложения, карточки действий, история сессий проекта, выбор модели), а не терминал.

### Лимиты и расход

- **Лимиты аккаунта** — из события `rate_limit_event` потока (проверено на 2.1.316; до чата —
  коротким запросом легкой модели, `claude_limits.rs`: сам при запуске, если данным больше
  15 минут, и по кнопке «Обновить»):
  `rate_limit_info.unifiedWindows.five_hour` и `.seven_day` — `utilization` (0–1), `resetsAt`
  (Unix), `status` (`allowed`, `allowed_warning`, `rejected`), плюс `surpassedThreshold`.
  Приходит после ответа API — показывается последнее известное значение с временем; до первого
  ответа в сессии — значение прошлого запуска из SQLite с пометкой «на HH:MM».
- **Где видно:** индикатор во второй строке (две тонкие полосы «Сессия 33 % · Неделя 78 %»,
  наведение — сброс через …), шапка чата; на пороге (`allowed_warning`) — желтый, при
  `rejected` — красный и сообщение в чате со временем сброса.
- **Расход по проектам:** из `result` каждого хода — `model_usage_since_last_result` (токены и
  оценка стоимости по моделям за этот ход), `num_turns`, `duration_ms`, `total_cost_usd`
  (накопительно за сессию — для суммы по сессии брать последний `result`), плюс изменение
  `utilization` окон между ходами. Пишется в `claude_turns` SQLite (проект, сессия, время,
  модель, токены, стоимость, длительность, доля окна до и после).
- **Замеры:** на проекте — сколько потрачено (ходы, токены, доля 5-часового окна и недели); на
  главной — в среднем на проект и на минуту готового ролика. Стоимость для подписки — оценка, не
  счет; в интерфейсе так и подписана.
- Приложение не читает учетные данные Claude и не ходит в сервисы Anthropic само — только то,
  что присылает установленный `claude`.

### Сборка подсказки

Каждое сообщение из чата = текст пользователя + **блок контекста**, собранный сервисом:

- выделение: клипы (дорожка, время, файл), точка воспроизведения, отмеченный диапазон;
- прикрепленное: файлы, перетащенные из медиа в чат, кадр предпросмотра (картинкой);
- быстрые действия — шаблоны сообщений с параметрами (кнопки над полем ввода: «Субтитры к
  выделенному», «Подогнать футаж под голос», «Проверить по правилам»; свои — в библиотеке).

**Постоянный контекст** — файл `--append-system-prompt-file`, собирается при открытии проекта и
при каждом изменении правил (процесс перезапускается с той же сессией); слои и память —
[assistant-layer.md](assistant-layer.md):

1. базовые правила студии (как устроен проект, какими инструментами что делать, нельзя писать
   файл проекта напрямую);
2. включенные правила библиотеки (общие стили и привычки монтажа);
3. правила проекта: `rules/brief.md`, `rules/rules.md`, `rules/style.md`, `rules/script.md`;
4. настройки последовательности (размер, частота, безопасные зоны).

Правила — обычные Markdown-файлы: их правит пользователь в редакторе «Подготовки» и Claude
(своими инструментами или инструментом `rules.update`), изменения видны обоим.

### Разбор ответа

Поток событий раскладывается по панелям:

| Событие | Куда |
| --- | --- |
| текст ассистента (по частям) | сообщение в чате, Markdown, печатается по мере прихода |
| вызов инструмента студии (`timeline.*`, `captions.*`, `audio.*`) | карточка действия в чате («Добавлен клип V2 0:03.20–0:05.00»), подсветка на таймлайне, одна группа отмены на ответ |
| `render.frame` | кадр в чате, клик — точка воспроизведения |
| `ui.ask` | вопрос с кнопками вариантов в чате |
| `ui.notify` | уведомление в углу окна |
| встроенные инструменты Claude (чтение файлов, команды) | свернутая строка «Читает rules/style.md», раскрывается |
| запрос разрешения | диалог «Разрешить / Разрешить всегда для проекта / Запретить» (`--permission-prompt-tool` → инструмент MCP студии) |
| итог хода (стоимость, время, ошибки) | строка под ответом, ошибка — с кнопкой «Повторить» |

Пока Claude отвечает: кнопка «Остановить», ввод не блокируется (следующее сообщение ждет в
очереди). «Отменить изменения Claude» — одна команда на весь ход.

### MCP-сервер студии

Сервер в ядре, HTTP на 127.0.0.1, порт и ключ — новые на каждый запуск, записываются в
`.studio/claude/mcp.json` чата проекта (`--strict-mcp-config`: других серверов у Claude нет).

**Сейчас (0.7, `src-tauri/src/mcp/`):** `project_summary` (проект, последовательность,
дорожки, длина, маркеры, головка, выделение, вкладка), `media_list`, `timeline_get` (клипы за
отрезок, строкой на клип), `timeline_apply` (пакет операций таймлайна — тех же, что у
интерфейса; один шаг отмены с подписью `claude#N`), `ui_seek`, `ui_select`, `ui_tab`,
`log_errors` (только по просьбе — кнопка ошибок в строке состояния). Ответы — короткий текст.
Разрешение `mcp__studio` — без вопроса. Пока Claude правит таймлайн, он заблокирован у
пользователя («Claude работает с таймлайном — подождите или прервите»); под ответом —
«Отменить изменения Claude» (весь ход одной командой, `project_undo_claude`). Интерфейс
сообщает головку, выделение и вкладку (`ui_state_report`). Сквозная проверка с настоящим
Claude — `cargo test live_claude_edits_timeline -- --ignored --nocapture`.

Задуманный полный набор:

| Группа | Инструменты |
| --- | --- |
| проект | `project.read` (последовательность, дорожки, клипы), `project.settings` |
| таймлайн | `timeline.add_clip`, `move`, `trim`, `split`, `delete`, `set_props`, `add_keyframes`, `add_marker` |
| медиа | `media.list`, `media.probe`, `media.import` |
| субтитры | `captions.align` (по голосу, по словам и слогам), `captions.set` |
| звук | `audio.process_voice` (громкость, компрессия), `audio.sfx` (из библиотеки или синтез), `audio.music_bed` (подложка под таймлайн, приглушение под голос) |
| умные клипы | `smart.create`, `smart.update` (файл `smart/*.tsx` + параметры), `smart.build` |
| рендер | `render.frame` (кадр PNG, чтобы Claude посмотрел результат), `render.video` (в очередь) |
| правила | `rules.read`, `rules.update` |
| инструменты пользователя | `tools.list`, `tools.run`, `tools.create`, `tools.update` ([extensions.md](extensions.md)) |
| интерфейс | `ui.ask`, `ui.notify`, `ui.select` (выделить клипы), `ui.seek` |

Все правки таймлайна — через сервис проекта: проверка схемы, история, событие в интерфейс.

## Данные и хранение

`.studio/claude/` проекта: `session.json` (ID сессии, модель), `system.md` (собранный
постоянный контекст), история чата для показа (`chat.jsonl`). Расход и последние лимиты — в
SQLite приложения (`claude_turns`, `claude_limits`). Модель и режим разрешений — в
настройках приложения, переопределяются в проекте.

## Правила

- Приложение не хранит ключи и вход Claude — только вызывает установленный `claude`.
- Claude меняет проект только инструментами студии; прямую запись `project.json` и
  `timeline.json` запрещают базовые правила и режим разрешений.
- Любое изменение от Claude отменяется одной командой.
